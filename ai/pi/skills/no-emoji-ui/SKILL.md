# No Emojis in UI Design

This skill enforces a strict rule: **never use emojis in any design, user interface (UI), component, mockup, or layout unless the user explicitly requests to use emojis.**

## Core Rules

1. **No Emojis by Default**:
   - Do not use emojis for icons, button labels, alerts, headings, navigation links, state indicators, or decorative elements.
   - For example, do not use 🚀, 🚨, ✅, ❌, ✨, or any other emojis in UI components.

2. **Alternatives to Emojis**:
   - Use plain text.
   - Use standard icons (e.g., Lucide, Heroicons, FontAwesome, Material Icons, or raw SVG shapes) where icons are needed.
   - Use appropriate colors, borders, or typography to indicate state or severity (e.g., red background/border for errors, green for success) instead of warning/error/check emojis.

3. **Explicit Consent Exception**:
   - Emojis may *only* be used if the user explicitly requests them (e.g., "Add a fire emoji to the call-to-action button", or "Make a playful UI with emojis").
